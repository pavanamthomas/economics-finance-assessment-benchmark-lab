# Uniqueness protocol

An accepted item has a unique key *under the stated assumptions*. The uniqueness paragraph must do two jobs:

1. Say why the keyed option is the only one compatible with those assumptions.
2. Name the unstated switch that *would* create a second defensible option, and confirm the stem shuts it.

If (2) cannot be written, the item is not ready. Typical switches: price convention (spot / average / post), equilibrium concept (open / closed city), reference point, information set (\(v\) vs \(p\)), timing (boom / stress), risk preference (CPT vs EU).

The rejected corpus is the library of failures of this protocol. Do not “repair” a two-key item by adding a footnote after the options that only the key-holder will read.
